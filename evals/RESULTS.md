## Method

- **Stage under test:** `app.services.kokoro_service._normalize_numbers` — the deterministic TTS-prep stage that converts digits to spoken words before synthesis.
- **Samples:** 10 fixed narration texts in `evals/samples.json`, covering years in context vs bare quantities, ordinals, fractions, phone numbers, money, decimals, percentages and times.
- **Correctness:** exact match against `evals/gold.json`. Gold strings were written by hand from the spoken-form rules and are the harness's expectations; a mismatch fails the run (exit code 1) and is shown below, not hidden.
- **Latency:** mean of 25 timed calls per sample after one warm-up call, on the machine that ran the harness.
- **Boundary:** the Kokoro TTS model itself is not executed by this harness (model weights are a local download, not a repo fixture) and no LLM provider is called, so synthesis quality and script-generation cost are out of scope. The cost column is a model built from the assumptions below — it is an estimate, not a measurement.

## Cost-model assumptions (estimates, not measurements)

- Narration pace: 150 words/minute of spoken output.
- TTS compute: 0.85 s of CPU per spoken word — the midpoint of the 0.7–1.0 s/word range documented for CPU synthesis in `backend/app/core/config.py`.
- Compute price: $0.046 per CPU core-hour (small cloud instance).
- The normalisation stage itself is measured above (sub-millisecond to a few milliseconds per script) and is negligible next to synthesis; rendering/encoding and any LLM script generation are excluded.
